# Портал «Заказ транспорта БЕ → РЦ»

Стартовый MVP-проект для GitHub + Supabase + RelaxDev.

## Состав
- React + TypeScript + Vite.
- Авторизация Supabase Auth по обезличенному логину и паролю (логин преобразуется в служебный адрес `@login.akson-transport.invalid`).
- Роли: `customer`, `dispatcher`, `utz`, `admin`.
- Календарь с тремя общими слотами на дату.
- Заявки, маршрут, грузоподъёмность, погрузка и типы груза.
- Права доступа на уровне PostgreSQL RLS.
- Edge Function для создания пользователей администратором.
- Журнал статусов и переносов дат.
- Логотип размещён в `public/apple-touch-icon.png`.

## Важные допущения текущей версии
1. Три слота общие для всего портала на каждую дату, а не три слота на каждую БЕ. Это соответствует формулировке `UNIQUE(transport_date, slot_number)` из исходного ТЗ. Если бизнес-правило другое, индекс надо изменить до запуска.
2. Для «Оборудование» дополнительных количественных полей пока нет — исходный запрос оставил этот вопрос без ответа.
3. Перенос даты доступен рабочим ролям через изменение заявки; проверку занятости обеспечивает уникальный индекс PostgreSQL.
4. УТЗ может работать со всеми заявками и пользователями по заданной матрице, но не управляет справочниками и настройками. В этой стартовой версии отдельные страницы администрирования справочников/пользователей ещё не реализованы; создание пользователя сделано через Edge Function.
5. Это исходный MVP-каркас, а не готовая к production эксплуатационная система. Перед публикацией обязательны тесты RLS под каждой ролью, проверка конкурентного бронирования, проверка переноса, и доработка административного интерфейса.

## 1. Подготовка Supabase
1. Создайте отдельный проект Supabase для этого нового портала.
2. Откройте SQL Editor.
3. Выполните `supabase/migrations/0001_initial_schema.sql`.
4. Создайте записи в `business_units` (тип `BE` или `RC`) через SQL Editor.
5. Разверните Edge Function:
   ```bash
   supabase functions deploy admin-create-user
   ```
6. Для функции используются стандартные Supabase secrets `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (service role не помещать во фронтенд).

### Первый администратор
После применения SQL создайте первого пользователя через Supabase Dashboard → Authentication → Users → Add user:
- email: `admin001@login.akson-transport.invalid`
- password: задайте длинный уникальный пароль (не менее 12 символов)
- отметьте Email confirmed.

Затем получите UUID пользователя и добавьте профиль через SQL Editor:
```sql
insert into public.profiles(id, username, role, is_active)
values ('UUID_ИЗ_AUTH_USERS', 'ADMIN001', 'admin', true);
```
Дальнейших пользователей создавайте через Edge Function `admin-create-user`. Не используйте service-role key в браузере.

## 2. Локальный запуск
```bash
cp .env.example .env
# заполните VITE_SUPABASE_URL и VITE_SUPABASE_ANON_KEY
npm install
npm run dev
```

Для Windows PowerShell вместо `cp`:
```powershell
Copy-Item .env.example .env
```

## 3. Публикация
1. Загрузите содержимое архива в новый GitHub-репозиторий.
2. Подключите репозиторий к RelaxDev.
3. Укажите build command `npm run build`.
4. Укажите output directory `dist`.
5. Добавьте переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в настройки окружения RelaxDev.
6. Выполните deploy.

## 4. Безопасность
- В клиенте используется только Supabase anon key.
- Service role key используется исключительно Edge Function.
- RLS включён на всех прикладных таблицах.
- Пользователь видит собственные заявки; рабочие роли видят все заявки.
- Только `admin` может управлять справочником и профилями.
- Открытая регистрация не используется.
- Не вставляйте персональные данные, секреты или пароли в GitHub.
- Не применяйте этот SQL к существующей базе другого приложения. Это схема нового портала.

## 5. Известные ограничения MVP
- Интерфейс календаря и формы реализован; отдельные административные страницы, полноценная история аудита с UI, экспорт Excel, фильтры, комментарии и UX-редактирование переноса требуют следующих этапов.
- Создание и обновление заявки сейчас разделено на несколько запросов; для production рекомендуется заменить на транзакционный RPC, чтобы данные заявки и груза сохранялись атомарно.
- Поля `Сток` и `КДК` отображаются в форме при выборе «Товар». При нескольких типах груза структура данных сохраняет количества в строках соответствующих типов.
- Сначала разверните на отдельном Supabase-проекте и проведите проверку. Не подключайте к production Supabase проекта «Аксон ДокСлот».
