# История изменений

## 0.4.2 — унификация грузовых полей и компактный календарь
- Поля количества груза приведены к единой сетке и одинаковой высоте ввода.
- Единицы измерения: Сток, Кросс док и Оборудование — паллетомест; Тара — штуки (шт.).
- Название поля «КДК» в форме заменено на «Кросс док»; структура хранения и CSV-поля не менялись.
- Высота календарных ячеек уменьшена на 20% для экранов desktop, mobile и узких телефонов; высота слотов пропорционально сокращена для сохранения пропорций.
- Другие функции, права, настройки и база данных не изменялись. SQL-миграция не требуется.

## 0.4.1 — грузоместа оборудования
- При выборе типа груза «Оборудование» в форме заявки появляется обязательное поле «Количество грузомест».
- Единица измерения указана как «паллетомест»; принимаются только целые положительные значения.
- Количество сохраняется отдельно в `request_cargo`, восстанавливается при редактировании, отображается в реестре заявок и включается в CSV.
- Добавлена серверная проверка и запись нового значения в журнал аудита.
- Добавлена миграция `0005_equipment_pallet_places.sql`; предыдущие настройки и права не менялись.

## 0.4.0 — разграничение ролей, календарь и отчёты

### Права доступа
- Заказчик видит только собственные заявки; может создавать их, редактировать до начала обработки и отменять только в статусе «Создана».
- Диспетчер видит все заявки, может редактировать их, менять статусы и отменять; дополнительно доступны история и отчёты. Создание заявок запрещено.
- УТЗ видит все заявки и календарь, может искать и выгружать данные, но не редактирует заявки, не меняет статусы и не отменяет их.
- Администратор сохраняет полные полномочия, включая создание заявок от имени любого активного заказчика, управление пользователями, справочниками и настройками.
- Правила закреплены в Supabase RLS и серверных функциях, а не только скрытием кнопок.
- Диспетчер и УТЗ могут читать деактивированные БЕ/РЦ для корректного отображения старых заявок; изменять справочник может только администратор.

### Календарь
- Свободные слоты отображаются знаком «+»; занятые — цветом текущего статуса и кодом БЕ отправления.
- В ячейке даты показывается сокращённое название месяца; дни соседних месяцев не предлагают фиктивные свободные слоты.
- Дата/слот открывают действия в пределах прав роли.
- Для диспетчера, УТЗ и администратора добавлены компактные фильтры по заказчику, отправлению/назначению, типу груза и тоннажу.
- Поиск учитывает код и название БЕ/РЦ, а также свободные адреса.
- Для заказчика календарная сводка по чужим заявкам ограничена статусом и кодом БЕ отправления.

### Отчёты и удобство
- Добавлена вкладка «Отчёты» для диспетчера и администратора.
- Доступны количество заявок по заказчикам, БЕ отправления и назначения, типам груза, распределение по срокам закрытия и незакрытым статусам.
- Выбранный период фильтруется по дате перевозки; скорость закрытия рассчитывается от создания до последнего перехода в статус «Выполнена» для заявок, которые сейчас выполнены.
- Добавлена CSV-выгрузка сводных показателей, всех таблиц и графиков.
- Добавлены подсказки при наведении на поля, списки и кнопки.
- История действий доступна диспетчеру и администратору; исправлен поиск по автору события без необходимости загружать весь список пользователей.

### Обновление базы данных
- Добавлена миграция `0004_role_permissions_calendar_reports.sql`.
- Миграцию выполнять после `0001_initial_schema.sql`, `0002_admin_workspace.sql` и `0003_admin_controls_audit.sql` в отдельном Supabase-проекте портала транспорта.
- Обновление клиента требует публикации фронтенда; Edge Functions создания/изменения пользователей остаются без изменений.

# Изменения — итерация 0.3.0

## Визуальная часть
- Интерфейс переведён на визуальный язык Аксон ДокСлот: фирменный логотип, градиентная линия, Inter, палитра Аксон, карточный интерфейс и светлая/тёмная темы.
- Добавлены боковая навигация и мобильное меню.
- Переработан экран входа; добавлено отображение/скрытие пароля.

## Функциональность
- Добавлен обзор показателей и ближайших заявок.
- Переработан календарь трёх общих слотов.
- Добавлен список заявок с поиском, фильтром статуса, сменой статуса и CSV-выгрузкой.
- Добавлены административные экраны пользователей и справочника.
- Добавлено включение/отключение пользователей и БЕ/РЦ.
- Для календаря добавлена минимальная безопасная выдача занятости слотов.

## Безопасность
- Добавлен `src/vite-env.d.ts` для типов Vite.
- Добавлена миграция `0002_admin_workspace.sql` с грантами, сохраняющими существующие RLS-ограничения.
- Ограничено изменение заказчиком только собственной заявки со статусом `created` и её груза.
- Создание пользователя выполняется только серверной Edge Function.

## Ограничения текущей версии
- Сохранение заявки и строк груза пока выполняется несколькими клиентскими запросами; для полной атомарности операцию следует вынести в транзакционный RPC.
- Комментарии, отдельная аналитика и XLSX-экспорт не входят в эту итерацию.


## Администрирование и контроль — 0.3.0
- Администратор может создавать заявки и редактировать любые заявки от имени выбранного активного заказчика.
- Добавлено редактирование логина, роли, бизнес-единицы, БЕ по умолчанию и пароля пользователя через защищённую Edge Function; смена логина синхронизируется с Supabase Auth.
- Добавлено редактирование кода, названия, типа и адреса БЕ/РЦ.
- Убрана промо-плашка «Управляйте транспортным потоком» на вкладке «Обзор» для всех ролей.
- Добавлены вкладки «Настройки» и «История» (доступны администраторам).
- Настройки поддерживают отдельный месячный лимит на пользователя для каждой роли и глобальный срок предварительной записи в днях.
- Новые серверные проверки не позволяют обходить лимит и срок предварительной записи прямыми запросами к Supabase.
- Журнал аудита фиксирует создание и изменение заявок, статусов, строк груза, профилей пользователей, справочника и настроек; поиск по пользователю, действию и деталям выполняется по всему архиву, добавлены фильтры по объекту и датам и постраничная загрузка по 500 событий.
- Добавлена миграция `0003_admin_controls_audit.sql` и Edge Function `admin-update-user`.

## Примечания по значениям по умолчанию
- Месячный лимит для каждой роли после миграции: 30 заявок на пользователя.
- Срок предварительной записи после миграции: 0 дней (разрешена запись день в день).
- Месячный лимит учитывает активные заявки по месяцу даты перевозки; отменённые заявки не учитываются.
- Для проверки срока используется бизнес-дата `Europe/Moscow`.


## v0.4.3 — необязательная БЕ заказчика и загрузка реестров

- Создание и редактирование пользователя с ролью «Заказчик» разрешает пустую БЕ.
- Новые заявки заказчика без БЕ профиля сохраняются с `business_unit_id = NULL`; фактическое место отправления задаётся отдельным полем маршрута.
- В форму создания/редактирования заявки добавлены необязательное вложение реестра и кнопка скачивания актуального шаблона.
- В «Настройках» администратор может загрузить или заменить шаблон реестра.
- Шаблон и реестры хранятся в приватном Supabase Storage bucket `dispatch-files`; доступ ограничен RLS-политиками Storage.
- Имя приложенного файла включено в CSV-выгрузку заявок; изменение вложения записывается в историю.
- Новая миграция: `0006_optional_customer_be_and_registry_files.sql`.
- Обновлены Edge Functions `admin-create-user` и `admin-update-user`.
