# Браузерные push-уведомления — настройка

Патч добавляет:
- всплывающие уведомления и историю в колокольчике;
- персональные уведомления в реальном времени;
- системные браузерные push-уведомления, в том числе когда вкладка закрыта;
- автоматическое удаление протухших push-подписок.

## 1. Загрузить файлы в GitHub

Заменить файлы:
- `src/App.tsx`
- `src/style.css`

Добавить:
- `public/sw.js`
- `public/push-setup.html`
- `supabase/migrations/0011_browser_push_notifications.sql`
- `supabase/functions/send-push/index.ts`

После коммита Vercel соберёт фронтенд. Для работы push нужен HTTPS — домен Vercel подходит.

## 2. Применить миграцию Supabase

Открыть Supabase → SQL Editor, вставить содержимое `supabase/migrations/0011_browser_push_notifications.sql` и выполнить один раз.

Миграция создаёт таблицы уведомлений и подписок, RLS-политики, адресные Realtime-каналы и триггер уведомлений на создание/изменение заявок. Существующие таблицы и заявки не пересоздаются.

## 3. Создать ключи

После деплоя открыть в браузере:

`https://ВАШ-ДОМЕН-VERCEL/push-setup.html`

Нажать «Сгенерировать ключи» и сохранить три значения в надёжном месте:
- `VAPID_PUBLIC_KEY` — публичный ключ;
- `VAPID_PRIVATE_KEY` — закрытый ключ;
- `DISPATCH_WEBHOOK_SECRET` — секрет для связи Database Webhook с Edge Function.

Не публиковать закрытый VAPID-ключ и webhook-секрет. Отключение Verify JWT безопасно только при обязательной проверке секретного заголовка, которая уже реализована в функции. Не генерировать новую пару после включения уведомлений пользователями: при смене VAPID-ключей подписки потребуется включить заново.

## 4. Развернуть Edge Function

В Supabase Dashboard открыть Edge Functions и создать функцию `send-push`.

Скопировать в редактор содержимое `supabase/functions/send-push/index.ts` и развернуть функцию. В настройках функции отключить стандартную проверку JWT (`Verify JWT`), поскольку Database Webhook авторизуется отдельным секретным заголовком `x-dispatch-webhook-secret`. Функция сама проверяет этот заголовок; без правильного секрета запросы отклоняются.

В настройках Secrets этой функции добавить:

| Имя | Значение |
|---|---|
| `VAPID_PUBLIC_KEY` | публичный VAPID-ключ из шага 3 |
| `VAPID_PRIVATE_KEY` | закрытый VAPID-ключ из шага 3 |
| `VAPID_SUBJECT` | `mailto:ваш-рабочий-email` |
| `DISPATCH_WEBHOOK_SECRET` | webhook-секрет из шага 3 |

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` функция получает из стандартного окружения Supabase Edge Functions. Service Role Key не добавлять в Vercel и не помещать во frontend.

## 5. Создать Database Webhook

Supabase Dashboard → Database → Webhooks → Create a new webhook:

- Name: `dispatch-push-notifications`
- Table: `public.user_notifications`
- Events: только `INSERT`
- Type: Supabase Edge Function
- Function: `send-push`
- HTTP Header: `x-dispatch-webhook-secret`
- Value: тот же `DISPATCH_WEBHOOK_SECRET` из шага 3.

Сохранить webhook. Он передаёт в Edge Function запись нового уведомления; сама функция отправляет push только подпискам пользователя-получателя.

## 6. Добавить публичный ключ в Vercel

Vercel → Project → Settings → Environment Variables:

- Name: `VITE_VAPID_PUBLIC_KEY`
- Value: `VAPID_PUBLIC_KEY` из шага 3
- Environments: Production (и Preview, если используется)

Сохранить и выполнить Redeploy. Закрытый ключ в Vercel не добавлять.

## 7. Включить push на устройствах

Каждый пользователь входит в Диспетчерскую, нажимает колокольчик → «Включить push» и разрешает уведомления в браузере. Это нужно сделать отдельно на каждом компьютере/телефоне и в каждом браузере.

Для теста создать новую заявку под заказчиком. У диспетчера и администратора должны появиться уведомление в колокольчике и всплывающее сообщение. При включённом push браузер покажет системное уведомление даже при закрытой вкладке.

## Кому и о чём приходят уведомления

- Новая заявка от заказчика → диспетчерам и администраторам.
- Заявка создана сотрудником от имени заказчика → заказчику и остальным ответственным сотрудникам.
- Отмена заявки заказчиком → диспетчерам и администраторам.
- Изменение статуса сотрудником → заказчику-заявителю.
- Изменение заявки заказчиком → диспетчерам и администраторам.
- Изменение заявки сотрудником → заказчику-заявителю.

УТЗ не получает уведомления о новых заявках. Содержимое push не включает маршрут, груз, адреса или реестр.

## Важные условия

- Push работает в защищённом контексте HTTPS и зависит от поддержки браузера и настроек уведомлений ОС.
- Если пользователь запретил уведомления, разрешение нужно изменить в настройках сайта браузера.
- Для отправки push при закрытой вкладке Edge Function и Database Webhook должны быть развёрнуты и активны.
- Если используется собственный домен, Service Worker должен быть доступен по адресу `/sw.js` на том же домене, что и приложение.
