# AksonDispatch v0.4.4 — патч

Основа: v0.4.3. Визуальная система портала сохранена.

## Что изменено

1. Заявку можно открыть для просмотра из календаря и списка заявок. В карточке все доступные поля отображаются в режиме просмотра; для редактирования используется пиктограмма карандаша в правом верхнем углу.
2. Заказчик может открывать только собственные заявки. Чужие заявки в его календаре отображаются только безопасной сводкой занятого слота.
3. Добавлены необязательные поля «Номер задания на перевозку» (до 44 символов) и «Комментарий» (до 320 символов).
4. Для роли УТЗ скрыта вкладка «Обзор»; после входа открывается «Календарь».
5. Заказчик может загрузить или заменить реестр своей заявки до её статуса «Выполнена» или «Отменена». После начала обработки остальные поля заявки остаются только для просмотра.
6. Диспетчер и администратор могут создавать и редактировать заявку на текущую или будущую дату независимо от настройки срока предварительной записи. Прошедшая дата запрещена для редактирования данных перевозки.
7. Для заказчика даты, недоступные из-за настройки предварительной записи, приглушены и не позволяют создавать заявку.
8. Правая панель календаря показывает только заявки, соответствующие активному поиску и фильтрам.
9. Добавлена защищённая Supabase Realtime-синхронизация: после изменения заявки все подключённые пользователи получают сигнал обновить данные, но не получают чужие поля из самого сигнала. Полные данные по-прежнему выдаются Supabase по RLS/RPC-правам каждой роли.

## Установка

1. Если миграция `0007_request_details_staff_booking_customer_registry.sql` ещё не применялась, выполните её первой.
2. Выполните `0008_realtime_request_refresh.sql`.
3. Опубликуйте фронтенд из архива через GitHub/Vercel.
4. Edge Functions не менялись относительно v0.4.3.

Не выполняйте повторно уже применённые миграции. SQL-миграции выполняйте в Supabase SQL Editor именно в проекте транспортного портала, не в проекте «Аксон ДокСлот».

## Проверка

Проверены синтаксис TS/TSX и структура ZIP. Полноценная сборка Vite и выполнение миграций на production Supabase не выполнялись в рабочем окружении; это нужно подтвердить после публикации.
